# Vue Stack Demo

End-to-end demo of Regrets' Vue 3 stack support (`capture_vue.mjs` +
`validate_vue.mjs`).

## What this demo proves

1. **Capture works**: `capture_vue.mjs` reads the manifest, renders each Vue 3
   component via SSR (`createSSRApp` + `renderToString`), normalizes the HTML,
   computes a fingerprint via `scripts/fingerprint.js` (same algorithm as
   JS/Python/Go/Rust stacks), and writes standard `.regret` files.
2. **Validate PASS works**: after no code changes, `validate_vue.mjs`
   re-renders, recomputes fingerprints, and reports PASS for all clusters.
3. **Validate FAIL works**: after a breaking refactor (currency position swap
   in `InvoiceCard.js`), `validate_vue.mjs` detects the divergence and reports
   FAIL with expected vs live hashes.
4. **Restore works**: after restoring the original code, validate PASS again.
5. **Cross-stack parity**: the Vue fingerprint matches the JS reference
   fingerprint for the same input/output pair.

## How to run

```bash
cd proof/vue_demo
bash run_demo.sh
```

Exit code 0 = demo passed (all 4 phases + parity check).

## Files

| File | Purpose |
|------|---------|
| `src/InvoiceCard.js` | Vue 3 component (defineComponent + render function) — main demo target |
| `src/StatusBadge.js` | Smaller Vue 3 component — demonstrates multiple clusters per manifest |
| `regrets/manifest.json` | 3 Vue cluster definitions (invoice card + 2 status badge variants) |
| `regrets/*.regret` | Golden contracts (generated by Phase 1; safe to delete + regenerate) |
| `run_demo.sh` | End-to-end demo driver: capture → PASS → break → FAIL → restore → PASS → parity check |

## Components in this demo

### InvoiceCard

Renders an invoice summary:
```html
<div class="invoice-card">
  <div class="invoice-header">
    <span class="invoice-id">INV-2026-001</span>
    <span class="status status-paid">PAID</span>
  </div>
  <div class="invoice-amount">USD 1250.50</div>
  <div class="invoice-customer">
    <div class="customer-name">Alice Anderson</div>
    <div class="customer-email">alice@example.com</div>
  </div>
</div>
```

The breaking change in Phase 3 swaps the currency formatting from
`"USD 1250.50"` to `"1250.50 USD"` — a tiny refactor that would silently
break downstream parsers if not caught.

### StatusBadge

Renders a colored badge: `<span class="badge badge-success badge-sm">Active</span>`.

Two clusters in the manifest use the same component with different props
(`variant: "success"` vs `variant: "warning"`) — demonstrates multi-input
capture across one component file.

## Why a Node-only demo (no .vue SFCs)

This demo uses render-function components in `.js` files (no `.vue` SFCs) to
avoid the `@vue/compiler-sfc` build step. v1 of the Vue stack supports
`.js` / `.mjs` components directly — see `references/vue.md` for the rationale
and the path to SFC support.

| `invoice-card-render` | invoice INV-2026-001, USD 1250.50, status paid | `30uqm2n` |

| `status-badge-warning` | label "Pending Review", variant warning, size md | `66k3v6p` |

parity contract holds for Vue.
