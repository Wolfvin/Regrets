# C# (.NET) Stack Variant

Regression fingerprinting for C# projects using a generated .NET harness project that invokes `public static` methods via reflection.

## Status: Working (capture + validate)

Both `capture_csharp.sh` and `validate_csharp.sh` are implemented and produce fingerprints **byte-for-byte identical** to the JS / Python / Go implementations. A complete end-to-end demo lives in `proof/csharp-demo/`.

---

## Quick Start

1. Install the .NET SDK 8+ on `PATH` (or set `DOTNET_CMD=/path/to/dotnet`).
2. Put your C# source files in `src/` (or set `REGRET_CSHARP_SRC=/path/to/src`).
3. Add `"stack": "csharp"` clusters to `regrets/manifest.json`.
4. Run `bash scripts/capture_csharp.sh` from your project root.
5. Run `bash scripts/validate_csharp.sh` after any refactor.
6. `.regret` files use the **identical** format to JS / Python / Go.

For a working walkthrough, run `bash verify_demo.sh` from `proof/csharp-demo/`.

## Manifest Schema (C# specific fields)

```jsonc
{

    {
      "id": "my-cluster",                    // → regrets/my-cluster.regret
      "entry": "MethodName",                 // public static method name
      "class": "MyNamespace.MyType",         // fully-qualified type name
      "stack": "csharp",                     // REQUIRED
      "fingerprintLevel": "entry",
      "watches": ["MethodName"],             // optional, informational
      "inputs": [                            // 1+ JSON values
        [2, 3],
        [10, 20]
      ]
    }
  ]
}
```

## The C# Regrets contract

A C# method is Regrets-eligible if it has this signature:

```csharp
public static object? MethodName(System.Text.Json.JsonElement input)
```

- **One parameter**: a `JsonElement` (whatever JSON value was in the cluster's `inputs` array — primitive, array, or object).
- **Return**: any JSON-serializable value (primitive, `List<>`, `Dictionary<,>`, POCO, `null`).
- **Throwing is allowed** — the exception's type + message becomes the captured `OUTPUT` (an `ERROR_CONTRACT` line is written instead of `OUTPUT`).

This matches the model "function(input) → output, both JSON-able" that Regrets already uses for JS / Python.

### Why a single `JsonElement` parameter?

C# is statically typed, but the manifest's `inputs` array can hold any JSON shape. Rather than have the manifest declare parameter types and the harness deserialize each one to its declared type, we pass the raw `JsonElement` and let the method read what it needs:

```csharp
public static object? Add(JsonElement input)
{
    int a = input[0].GetInt32();   // method decides how to interpret input
    int b = input[1].GetInt32();
    return a + b;
}
```

This keeps the manifest schema stack-neutral (no per-stack type annotations) and avoids reflection-based deserialization pitfalls.

## Architecture

```
scripts/
├── RegretFingerprint.cs     # StableStringify + Fingerprint + FindType (reflection helper)
├── capture_csharp.sh        # Reads manifest, generates regrets/_regret_capture/ project,
│                            # compiles + runs it, writes .regret files
└── validate_csharp.sh       # Reads .regret files, generates regrets/_regret_validate/ project,
                             # compiles + runs it, compares live hash vs golden hash
```

The harness projects are **ephemeral** — they are regenerated on every `capture` / `validate` run and deleted on success (unless `--verbose` is passed). They live under `regrets/_regret_capture/` and `regrets/_regret_validate/`, both of which are in `.gitignore`.

The harness project includes:
- `RegretFingerprint.cs` (copied from `scripts/`)
- `RegretCapture.cs` (or `RegretValidate.cs`) — generated by the bash runner
- All `*.cs` files from the user's `src/` directory (referenced via `<Compile Include="..." />`)

## Cross-stack fingerprint parity

The fingerprint algorithm is **identical** across JS, Python, Go, Rust, PHP, and C#:

```
combined  = stableStringify(input) + "|" + stableStringify(output)
hash      = sha256(combined)               // 64-char lowercase hex
num       = BigInt("0x" + hash)            // always positive
b36       = num.toString(36)               // base-36, lowercase
fp        = b36.slice(0, 7)                // first 7 chars
```

In C#, the BigInteger construction has one subtle gotcha: `new BigInteger(byte[])` expects **little-endian** bytes, and the most-significant bit of the last byte is the sign bit. We:
1. Convert the hex string to bytes in big-endian order.
2. Reverse in place so they're little-endian.
3. Append a `0x00` byte so the number is always interpreted as positive (matching JS `BigInt('0x' + hex)`).

This is implemented in `RegretFingerprint.PositiveBigIntegerFromHex`. Without the trailing `0x00`, hashes whose last byte has its MSB set would produce empty fingerprints (the `while (n > 0)` loop never executes on a negative `n`).

### Verification

For every input in `proof/csharp-demo/regrets/manifest.json`, the C# implementation produces the **same** 7-char fingerprint as the Python reference:

| Cluster              | Input      | Output                          | Fingerprint |
|----------------------|------------|---------------------------------|-------------|
| `calc-add`           | `[2,3]`    | `5`                             | `13mxb0z`   |
| `calc-add`           | `[10,20]`  | `30`                            | `560s4tf`   |
| `calc-add`           | `[-5,7]`   | `2`                             | `41dkf14`   |
| `calc-add`           | `[0,0]`    | `0`                             | `536pw5k`   |
| `calc-add`           | `[100,200]`| `300`                           | `65bacti`   |
| `calc-reverse`       | `"hello"`  | `"olleh"`                       | `5nssd6s`   |
| `calc-reverse`       | `"Regrets"`| `"stergeR"`                     | `h0sx12s`   |
| `calc-reverse`       | `"racecar"`| `"racecar"`                     | `4uyjrfr`   |

Reproduce locally:

```bash
python3 -c "
import hashlib, json
def ss(x):
    if isinstance(x, list): return '[' + ','.join(ss(v) for v in x) + ']'
    if isinstance(x, str): return json.dumps(x)
    return str(x)
combined = ss([2,3]) + '|' + ss(5)
h = hashlib.sha256(combined.encode()).hexdigest()
n = int(h, 16)
b36 = ''
while n > 0:
    n, r = divmod(n, 36)
    b36 = '0123456789abcdefghijklmnopqrstuvwxyz'[r] + b36
print(b36[:7])  # → 13mxb0z
"
```

## Multi-input support (issue #315 pattern)

If a cluster's `inputs` array has more than one entry:

- `INPUT[0] / OUTPUT[0] / HASH` are written at the top level (same as single-input case).
- `INPUT[1+]` are written into an `INPUTS` JSON array line at the end of the file:

  ```
  INPUTS [{"input":[10,20],"output":30,"hash":"560s4tf","threw":false}, ...]
  ```

`validate_csharp.sh` re-runs every input and compares every hash — any mismatch FAILs the cluster. This matches the JS / Python implementation (issue #315).

## Out of scope (for now)

These are intentionally **not** implemented in this PR — see issue #350 for rationale:

- **Callee wrapping (Phase 2)** — would require Roslyn source-generation or IL weaving; deferred to a follow-up.
- **Generic methods** — type-erasure handling is non-trivial.
- **`async Task<T>` return values** — need sync-over-async handling.
- **ASP.NET / application framework integration** — too many side effects to fingerprint deterministically.
- **Instance methods** — the manifest would need `constructorArgs` / `instanceMethods` fields. The harness could be extended; for now, expose your logic as `public static`.

These limits are documented in the issue and in the script headers.
